## Phase 1 — acceptance

- [x] pnpm monorepo: `apps/api`, `apps/web`, `packages/db`, strict TypeScript everywhere.
- [x] Environment validated at boot (Zod); `.env.example` documents every variable; no secrets in source.
- [x] Express app with request IDs, structured logging (credentials redacted), Helmet, rate limiting, CSRF origin check, JSON errors.
- [x] `/health` checks MySQL — verified against **MySQL 8.0.46, all tables InnoDB**.
- [x] Next.js app proxies `/api` and `/media` to the API (single origin).
- [x] docker-compose (MySQL 8 + MinIO), API Dockerfile, GitHub Actions CI with MySQL service and migration-drift check.
- [ ] Abacus environment verified (blocked: no access from sandbox).

## Phase 2 — acceptance

- [x] All 22 required tables + supporting tables (sessions, tokens, sizes, colours, collections, inventory ledger, refunds, shipping zones/methods, content, settings).
- [x] Initial migration generated by Prisma and applied; `migrate diff` confirms zero drift.
- [x] Idempotent base seed (categories, size systems, colours, shipping, content, owner account).
- [x] Optional demo seed with flagged placeholder images, removable with `--purge`.
- [x] Admin auth (Argon2id, hashed sessions, lockout), RBAC, audit log.
- [x] Product admin API: CRUD, publish checks, archive, colour×size matrix generation, SKUs, per-variant price override, inventory set/adjust with ledger, image upload/reorder/delete (validation + EXIF strip), brands, category tree (cycle-safe), size systems, colours.
- [x] 31 integration tests against real MySQL — all passing.

## Phase 3 — acceptance

- [x] Design tokens from the brief's palette; Bodoni Moda (display) + Jost (UI), self-hosted.
- [x] Announcement bar (rotating, pausable, admin-managed), sticky header with mega-menu, accessible mobile drawer (focus trap, Esc, scroll lock).
- [x] Split editorial hero (admin-managed slides, per-campaign colour field, slide index, reduced-motion aware).
- [x] Service strip, new arrivals, asymmetric collections, editorial feature, bestsellers (sales-ranked, curated fallback), newsletter with consent + success/error states, footer.
- [x] Product cards: hover second image, brand, price, sale price + %, colour swatches, sold-out state, wishlist toggle (guest, local; merged into account in Phase 5).
- [x] Placeholders are labelled on screen and to screen readers; never presented as merchandise.
- [x] Verified at 1440 px and 390 px.

Links to category, product, search, account, bag and help pages currently show the styled 404 page; those
pages are built in Phases 4–8.

## Phase 7 prerequisites (owner action)

Card payments need a merchant account. The brief suggests **Monri** or **AllSecure**; their availability for the business's country of registration still has to be confirmed with each provider.
Needed from the provider once approved: test + live merchant credentials, webhook signing secret, supported
currencies (EUR), refund API access. Until then the footer lists only cash on delivery.
